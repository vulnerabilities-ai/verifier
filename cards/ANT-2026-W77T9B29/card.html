ANT-2026-W77T9B29: CI downloads unverified binary then assumes production AWS role

The qemu-image-build GitHub Actions workflow downloads yq from a mutable GitHub release URL with no SHA-256 verification, chmods it executable, and runs it. The same job subsequently calls aws-actions/configure-aws-credentials to assume secrets.CONTROL_PLANE_PROD_ROLE via OIDC. Because GitHub release assets can be replaced in-place, a compromised mikefarah/yq maintainer could swap the v4.45.1 arm64 asset for a trojan that waits for the AWS credentials to be configured and exfiltrates them. Those STS credentials grant whatever the prod control-plane role can do (publish AMIs, write artifact buckets), cascading into downstream customer impact.

Target

Project: supabase/postgres
Location: .github/workflows/qemu-image-build.yml:72
Discovery: static analysis — not yet dynamically reproduced

Technical Details

curl -L .../mikefarah/yq/releases/download/v4.45.1/yq_linux_arm64 -o yq && chmod +x yq fetches a release asset that the upstream repo can silently replace without changing the tag, and no checksum is verified before execution. The downloaded binary runs with the job's filesystem and environment, so it can read ~/.aws, AWS_* env vars, or the metadata hop once configure-aws-credentials populates them.

Reproduction

  1. Compromise a mikefarah/yq maintainer token or gain repo write access
  2. Re-upload the v4.45.1 yq_linux_arm64 asset with a trojan that forks a background process polling for AWS_* env vars / ~/.aws/credentials and POSTs them out
  3. Wait for the next push to supabase/postgres to trigger the qemu-image-build workflow
  4. Trojan runs, waits for configure-aws-credentials to assume CONTROL_PLANE_PROD_ROLE, exfiltrates the STS credentials
  5. Use the stolen credentials to push a backdoored AMI that is rolled out to customers

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

Pin a SHA-256 for every executable fetched in CI (or install from a pinned, immutable source) and verify it before execution. Isolate jobs that assume production cloud roles from jobs that download/execute third-party binaries so a compromised tool cannot reach prod credentials.
