ANT-2026-6JWE6ZK7: VFS sandbox executes agent commands directly on host

The VfsSandbox backend in @langchain/node-vfs is documented and advertised to the LLM as an isolated execution environment, but its execute() method simply runs /bin/bash -c <command> on the host with env: { ...process.env } and only cwd pointed at a temp directory. There is no chroot, namespace, container, or environment filtering, so absolute paths, host processes, the network, and every secret in process.env are reachable. An attacker who gets prompt-injection content into the agent's context can induce the execute tool to run arbitrary host commands, exfiltrating API keys and cloud credentials or achieving persistence. This is strictly worse than LocalShellBackend, which carries an explicit no-sandboxing warning and defaults to inheritEnv:false, while VfsSandbox has neither safeguard and sits alongside genuinely isolated providers (Modal, Deno, Daytona), misleading developers about its guarantees.

Target

Project: langchain-ai/deepagentsjs
Location: libs/providers/node-vfs/src/sandbox.ts:346
Discovery: static analysis — not yet dynamically reproduced

Technical Details

The root cause is that execute() provides no actual OS-level isolation: it calls bash in-process with the full host environment and filesystem accessible, contradicting the README and tool-description claims of an isolated sandbox. Additionally, #syncDirFromTemp (lines 260-278) does not reject symlinks, so even after isolating the subprocess an attacker could read host files by planting a symlink in the shared temp directory.

Reproduction

  1. Developer deploys an agent using VfsSandbox, trusting the documented isolation claim
  2. Attacker supplies content (e.g., a document to summarize) containing a prompt-injection payload
  3. The agent follows the injected instruction and invokes the execute tool with an attacker-chosen shell command
  4. VfsSandbox.execute() spawns /bin/bash -c on the host with full process.env, running the command with host privileges
  5. Command exfiltrates env secrets (e.g., ANTHROPIC_API_KEY, cloud creds), reads ~/.ssh/id_rsa, or writes to ~/.bashrc for persistence

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

Either run agent-driven commands inside a real OS-level sandbox (container/namespace/microVM) that cannot reach host filesystem, network, or environment beyond the synced workspace, or drop the isolation claim and add a LocalShellBackend-style security warning; in all cases stop inheriting process.env into agent subprocesses, and harden #syncDirFromTemp to reject symlinks.
