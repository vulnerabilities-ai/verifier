ANT-2026-8RX9XHEB: Heap out-of-bounds write in font loader via stride miscalculation

In PHP_FUNCTION(imageloadfont) at ext/gd/gd.c:543, the loop that reads the font header passes &font[b] as the destination buffer, where font is a typed gdFontPtr rather than a char*. Pointer arithmetic therefore scales the offset by sizeof(gdFont) (~24 bytes) instead of 1. If the first php_stream_read() returns fewer than hdr_size bytes, b is set to that byte count and the next iteration writes to (char*)font + b*24, well beyond the single-struct allocation. An attacker who can influence the font stream — via an uploaded file, a URL wrapper, or any transport that produces a short read — controls the bytes written at this predictable out-of-bounds heap offset, corrupting adjacent zend_mm metadata or live objects and enabling a heap-grooming path to code execution.

Technical Details

The root cause is incorrect pointer arithmetic: &font[b] indexes a gdFontPtr, so each unit of b advances sizeof(gdFont) bytes rather than one byte. After a partial read of n bytes, the resumed read targets (char*)font + n*sizeof(gdFont) instead of (char*)font + n, landing outside the ~24-byte header buffer and writing attacker-supplied data onto neighboring heap memory.

Reproduction

  1. Identify an endpoint that passes user-controlled data to imageloadfont() (e.g., theme/font upload or remote font URL).
  2. Serve or upload a font stream engineered so the initial php_stream_read() returns n < hdr_size bytes.
  3. On the next loop iteration, PHP writes attacker-chosen bytes to (char*)font + n*sizeof(gdFont).
  4. Groom the heap so the OOB write lands on zend_mm chunk metadata or a live object.
  5. Leverage the corrupted metadata/object to achieve arbitrary code execution.

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

Cast the destination to a byte pointer before indexing (e.g., use ((char*)font) + b) so partial reads resume at the correct byte offset within the allocated header buffer.

+--TEST--
+imageloadfont(): header read must stay in bounds on short reads
+--EXTENSIONS--
+gd
+--FILE--
+<?php
+/* A user-space wrapper returns one byte per read, so php_stream_read() hands
+ * imageloadfont()'s header loop a short read on every iteration. The header
+ * (4 ints) plus a single 1x1 glyph byte form a valid font, which only loads
+ * when each short read lands at the correct byte offset. */
+class drip
+{
+    public $context;
+    private string $data;
+    private int $pos = 0;
+
+    public function stream_open($path, $mode, $options, &$opened): bool
+    {
+        $this->data = pack('V4', 1, 32, 1, 1) . "\x00";
+        return true;
+    }
+
+    public function stream_read($count): string
+    {
+        return $this->pos < strlen($this->data) ? $this->data[$this->pos++] : '';
+    }
+
+    public function stream_eof(): bool
+    {
+        return $this->pos >= strlen($this->data);
+    }
+
+    public function stream_stat()
+    {
+        return [];
+    }
+
+    public function stream_tell(): int
+    {
+        return $this->pos;
+    }
+
+    public function stream_seek($offset, $whence): bool
+    {
+        if ($whence === SEEK_CUR) {
+            $this->pos += $offset;
+        } elseif ($whence === SEEK_END) {
+            $this->pos = strlen($this->data) + $offset;
+        } else {
+            $this->pos = $offset;
+        }
+        return true;
+    }
+
+    public function stream_set_option($option, $arg1, $arg2): bool
+    {
+        return false;
+    }
+}
+
+stream_wrapper_register('drip', drip::class);
+var_dump(imageloadfont('drip://font') instanceof GdFont);
+?>
+--EXPECT--
+bool(true)
