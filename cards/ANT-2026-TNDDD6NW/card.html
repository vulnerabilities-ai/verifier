ANT-2026-TNDDD6NW: Stack buffer overflow in mpegts.c pmt_cb via multiple IOD

The MPEG-TS PMT parser in libavformat/mpegts.c allocates a fixed 16-entry (1152-byte) Mp4Descr array on the stack and, for each IOD_DESCRIPTOR in the program_info loop, calls mp4_read_iods() with a base pointer offset by the accumulated count but a constant limit of MAX_MP4_DESCR_COUNT (16). mp4_read_iods()/init_MP4DescrParseContext() reset the local descr_count to 0, so the bounds check in parse_MP4ESDescrTag compares 0 against 16 and always passes. A PMT containing two IOD descriptors of 16 ESDescrs each fills slots 0..15 on the first pass and then writes slots 16..31 on the second, overflowing the stack array by 1152 bytes. The bug fires inside avformat_open_input(), so simply running ffprobe on a crafted file is enough to trigger it.

Target

Project: ffmpeg/ffmpeg
Version: commit fec2836483 (Oct 2011) through current master
Location: parse_MP4ESDescrTag() at libavformat/mpegts.c:1570; called from pmt_cb() at mpegts.c:2616

Technical Details

ASAN: "stack-buffer-overflow WRITE of size 4 at 0x73054bb01b60" in parse_MP4ESDescrTag (mpegts.c:1570). The root cause is that pmt_cb() passes mp4_descr + mp4_descr_count as the destination but still passes the full MAX_MP4_DESCR_COUNT as the limit, and mp4_read_iods() resets its internal counter to 0 and later overwrites (rather than increments) *descr_count. The per-call bounds check d->descr_count >= d->max_descr_count therefore never accounts for entries written by earlier IOD descriptors, allowing d->active_descr = d->descr + (d->descr_count++) to point past the end of the stack array.

Reproduction

  1. Craft an MPEG-TS stream with a PMT whose program_info loop contains two IOD_DESCRIPTOR entries.
  2. Populate each IOD with 16 ESDescr entries (MAX_MP4_DESCR_COUNT).
  3. Deliver the file to the target (e.g. upload to a transcoding service, or get a user to run ffprobe/ffmpeg on it).
  4. avformat_open_input() parses the PMT; the first IOD fills mp4_descr[0..15]; the second IOD receives base = mp4_descr+16 with a fresh limit of 16 and writes mp4_descr[16..31], 1152 bytes past the stack array.

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

In mp4_read_iods(), accumulate into the caller's count (*descr_count += d.descr_count) instead of assigning, and in pmt_cb() pass the remaining capacity (MAX_MP4_DESCR_COUNT - mp4_descr_count) rather than the full constant, so subsequent IOD descriptors cannot exceed the stack array. The reporter notes multiple IODs appear to be permitted by ISO/IEC 13818-1:2007 §2.6.40, so rejecting a second IOD outright may not be spec-compliant.
