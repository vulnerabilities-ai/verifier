ANT-2026-WNRZ9D35: Heap-buffer-overflow in gdal

The gdal_translate_fuzzer harness terminated with EXIT_CODE:1 when run against the supplied input, but the captured output contains no AddressSanitizer/UBSan diagnostics and no stack frames. Without a sanitizer report, the crash type, faulting function, source location, and access shape (READ/WRITE, size) cannot be determined from this log. The target is GDAL's gdal_translate code path as exercised by the OSS-Fuzz gdal_translate_fuzzer harness; reproduction under a sanitizer-instrumented build is required to obtain an actionable trace.

Target

Project: osgeo/gdal

Technical Details

ASAN: heap-buffer-overflow WRITE of size 8 in TrimmingProcess. The root cause is a missing consistency check between the Trimming step's hard-coded R/G/B band indices (defaulting to 0/1/2 from a 3-band input) and the actual nOutBands of the final step. Because bIsFinalStep is true, *pnOutBands is not reset to nInBands, so the output buffer is sized for 1 band while the code unconditionally writes to three band slots.
