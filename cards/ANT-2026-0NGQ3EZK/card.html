ANT-2026-0NGQ3EZK: TOFU trust bypass via forged certification without signature verification

In the TOFU trust model, signed_by_utk() and cross_sigs() (g10/tofu.c) decide whether a new key is trusted by scanning certification-signature packets and comparing sig->keyid against the ultimately-trusted-key list via tdb_keyid_is_utk(). The issuer keyid is an unauthenticated subpacket copied verbatim from the imported key, and neither function calls check_key_signature() to verify the certification. An attacker who appends a fabricated 0x13 certification claiming the victim's own UTK keyid to their key causes signed_by_utk() to return 1, get_policy() to assign TOFU_POLICY_GOOD, and tofu_get_validity() to return TRUST_FULLY. Default gpg --import does not set IMPORT_SELF_SIGS_ONLY or IMPORT_CLEAN, and key_check_all_keysigs() detects the bad signature but never deletes the node, so the forged packet reaches the keyring and the TOFU evaluator. The attacker's key is then treated as fully trusted with no prompt, letting them pass signature verification and receive encrypted traffic.

Target

Project: gpg/gnupg
Location: g10/tofu.c:1489
Discovery: static analysis — not yet dynamically reproduced

Technical Details

At tofu.c:1508, signed_by_utk() calls tdb_keyid_is_utk(sig->keyid) — a pure 64-bit keyid comparison against utk_list — on raw signature packets from the keyblock, with sig->keyid populated verbatim from the attacker-supplied SIGSUBPKT_ISSUER subpacket (parse-packet.c:2267). No check_key_signature()/check_signature_over_key_or_uid() is invoked anywhere in signed_by_utk() or cross_sigs(), so the claimed issuer identity is trusted without any cryptographic verification. merge_selfsigs() only verifies self-sigs, and the import path (chk_self_sigs, delete_inv_parts, key_check_all_keysigs) leaves well-formed third-party certs in the keyblock even when detected as bad, so the forged packet survives to the trust decision.

Reproduction

  1. Generate an attacker keypair for the target identity (e.g. alice@example.org).
  2. Append a fabricated 0x13 certification signature packet to the attacker key's UID, setting the Issuer subpacket to the victim's ultimately-trusted key's 64-bit keyid (public information).
  3. Distribute the crafted public key via WKD, LDAP keyserver, email attachment, or any channel leading to gpg --import / --locate-keys.
  4. Victim imports the key; default import options do not strip the forged third-party certification.
  5. On first use, TOFU's get_policy() → signed_by_utk() matches the forged keyid against the UTK list and sets TOFU_POLICY_GOOD → TRUST_FULLY with no conflict prompt.
  6. Attacker sends signed messages that gpg --verify reports as good with full validity, and/or receives mail encrypted to the attacker key as if it were Alice's.

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

Cryptographically verify any certification signature (via check_key_signature or equivalent) against the claimed issuer's public key before using its issuer keyid in signed_by_utk()/cross_sigs() trust decisions.
