ANT-2026-HJ61D4C3: Heap-buffer-overflow in vf_boxblur.c:157

A 3040-byte crafted MKV containing a 128x128 gbrp HEVC stream, when processed through FFmpeg's boxblur filter with radius expression min(w,h)/2, triggers a 1-byte out-of-bounds heap read in blur8 at libavfilter/vf_boxblur.c:157. The overflow occurs during vertical blur processing via the call chain vblur → blur_power → blur → blur8, reading past a 16448-byte heap allocation. The bug is deterministic: three independent runs in a fresh container produced identical ASAN reports. An attacker who can supply input to an FFmpeg pipeline using boxblur can at minimum cause a crash (DoS) and potentially leak adjacent heap memory.

Target

Project: ffmpeg/ffmpeg
Location: vf_boxblur.c:157

Technical Details

ASAN: READ of size 1 past the end of a 16448-byte heap region in blur8 (vf_boxblur.c:157). During the vertical blur pass, the blur kernel indexes one byte beyond the allocated plane buffer when the blur radius is derived from min(w,h)/2 on a 128x128 gbrp frame, indicating a missing or off-by-one bounds check on the source pointer in the inner blur loop.

Crash trace:

The PoC (3040-byte MKV file) triggers a deterministic heap-buffer-overflow in FFmpeg's boxblur video filter. When processed with the command `/src/ffmpeg/ffmpeg -y -i /tmp/poc_boxblur_heap_overflow.mkv -vf "boxblur=min(w\,h)/2" -frames:v 1 -f null -`, ASAN detects a READ of size 1 past the end of a 16448-byte heap allocation in the `blur8` function at `libavfilter/vf_boxblur.c:157`. The crash occurs in thread T7 during vertical blur processing (`vblur` → `blur_power` → `blur` → `blur8`). The bug is in the boxblur filter's frame processing when handling a 128x128 gbrp HEVC video. All 3 reproduction runs in a fresh container produced identical ASAN reports with exit code 1. This is a genuine, security-relevant heap-buffer-overflow vulnerability in FFmpeg's filter code.

Reproduction

  1. Craft a 128x128 gbrp HEVC stream muxed into MKV (PoC is 3040 bytes)
  2. Have the target run: ffmpeg -i poc.mkv -vf "boxblur=min(w\,h)/2" -frames:v 1 -f null -
  3. During vblur → blur_power → blur → blur8, a 1-byte OOB heap read occurs and ASAN aborts
