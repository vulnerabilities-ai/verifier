ANT-2026-F5JK7RDG: Cloud image provisioned with default root password and SSH password auth

The cloud-init user-data baked into the QEMU/Nix image build (referenced by qemu-arm64-nix.pkr.hcl:96 as ssh_password = "ubuntu") assigns the crypt hash of the plaintext 'ubuntu' to both the root and ubuntu accounts, sets lock_passwd: false, and enables ssh_pwauth: True. No subsequent provisioner re-locks these accounts or disables password authentication before the image is captured. Any instance booted from this artifact on a network-reachable host can be logged into as root over SSH with a known password. This yields full control of the database, all tenant data, and a foothold for lateral movement.

Target

Project: supabase/postgres
Location: user-data-cloudimg:3
Discovery: static analysis — not yet dynamically reproduced

Technical Details

The root cause is that build-time convenience credentials are baked into the shipped artifact: cloud-init sets a known password hash for root/ubuntu with lock_passwd: false and ssh_pwauth: True, and the Packer pipeline never revokes them in a cleanup step, so the captured image ships with remotely usable default root credentials.

Reproduction

  1. Operator or CI launches the QEMU-built supabase/postgres image on a host with port 22 reachable
  2. Attacker runs ssh root@<ip> and enters password 'ubuntu'
  3. Attacker receives an interactive root shell

[No reproducer or sanitizer output attached — request from security-cvd@anthropic.com if needed.]

Suggested Fix

Never ship build artifacts with password authentication or known credentials: lock all local accounts and set ssh_pwauth: false before image capture, and have Packer authenticate via an ephemeral SSH key that a final cleanup provisioner removes.

UPSTREAM FIX

The change that resolved this finding.

diff --git a/ebssurrogate/scripts/qemu-bootstrap-nix.sh b/ebssurrogate/scripts/qemu-bootstrap-nix.sh
index 43e1d98fa7..a76186bf75 100755
--- a/ebssurrogate/scripts/qemu-bootstrap-nix.sh
+++ b/ebssurrogate/scripts/qemu-bootstrap-nix.sh
@@ -156,6 +156,19 @@ function clean_system {
 	rm -rf /root/.vpython*
 	rm -rf /root/go
 	rm -rf /mnt/usr/share/doc
+
+	# remove passwords in user-data-cloudimg.img (required for Packer login)
+	usermod -p '*' ubuntu
+	usermod -p '*' root
+
+  # Ensure that PasswordAuthentication is off
+  # From chroot-boostrap-nix.sh
+  sed -i -E \
+    -e 's/^#?\s*PasswordAuthentication\s+(yes|no)\s*$/PasswordAuthentication no/g' \
+    -e 's/^#?\s*ChallengeResponseAuthentication\s+(yes|no)\s*$/ChallengeResponseAuthentication no/g' \
+    /etc/ssh/sshd_config
+  grep -qE "^PasswordAuthentication\s+no" /etc/ssh/sshd_config \
+    || { echo "ERROR: PasswordAuthentication is not disabled in sshd_config"; exit 1; }
 }
