ANT-2026-8AZGCAHG: Heap-buffer-overflow in gdal

Running the reproducer through gdal_filesystem_fuzzer produced a non-zero exit (EXIT_CODE:1) but no AddressSanitizer/UBSan diagnostic or stack frames were printed. Without a sanitizer tag, access shape, or crashing frame, the fault type and sink cannot be determined from this log alone. The target is GDAL's virtual filesystem layer, so the trigger is presumably a crafted filesystem/archive input, but this is inferred solely from the fuzzer name.

Target

Project: osgeo/gdal

Technical Details

ASAN: heap-buffer-overflow WRITE of size 65536 into a 1-byte region allocated by VSI_CALLOC_VERBOSE. Root cause: oColorTable.BytesPerRecord is a GUInt32 assembled from two 16-bit extended-DBF header fields; with both set to 0xFFFF it becomes 0xFFFFFFFF, and nBufferSize = BytesPerRecord + 1 wraps to 0, so calloc(1, 0) yields a 1-byte buffer while VSIFReadL(pzsRecord, 1, BytesPerRecord, ...) still reads with the unwrapped 32-bit length.

Reproduction

Reproduce against the target as described under Technical Details.

Suggested Fix

Validate BytesPerRecord against a sane upper bound (and against file size) before allocating, and compute nBufferSize in a wider type or reject when BytesPerRecord + 1 overflows GUInt32.
